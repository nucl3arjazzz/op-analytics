# OP-analytics

Автоматичний збір даних з OpenProject для тижневої аналітики по задачах команди.

Репозиторій відповідає за першу половину системи: **збір даних**. Аналіз і формування звіту робить окремий skill, який читає `data/latest.json`.

## Що збирається

| Дані | Звідки | Навіщо |
|---|---|---|
| Робочі пакети (включно із закритими) | `/api/v3/work_packages` | статуси, виконавці, дати, оцінка, відсотки |
| Статуси та ознака «закритий» | `/api/v3/statuses` | коректно відрізняти відкриті й закриті задачі |
| Історія переходів статусів | `/api/v3/work_packages/{id}/activities` | cycle time, час у статусах, повернення назад |
| Облік часу | `/api/v3/time_entries` | години по людях за тиждень |

Кожен запуск пише `data/latest.json` і копію `data/snapshots/РРРР-ММ-ДД.json`. Знімки накопичуються, тому тренди між тижнями доступні навіть без історії в самому OpenProject.

## Налаштування

1. **Токен.** В OpenProject: *Мій обліковий запис → Токени доступу → API → Створити*. Краще окремий користувач з правами лише на читання (перегляд задач і перегляд записів часу).
2. **Секрети репозиторію** (*Settings → Secrets and variables → Actions → Secrets*):
   - `OP_BASE_URL`: адреса, напр. `https://openproject.example.com`
   - `OP_API_KEY`: токен з кроку 1
3. **Змінні** (необов'язково, там же, вкладка *Variables*):
   - `OP_PROJECT_ID`: id або identifier проєкту (інакше беруться всі доступні)
   - `TIME_LOOKBACK_DAYS`: глибина історії обліку часу, за замовчуванням 90
4. Запустити вручну: *Actions → Збір даних з OpenProject → Run workflow*. Далі запускається сам щопонеділка зранку.

Репозиторій має бути **приватним**: у даних є імена людей і назви задач.

## Локальний запуск

```bash
pip install requests
export OP_BASE_URL=https://openproject.example.com
export OP_API_KEY=...
python scripts/collect_openproject.py
```

## Відомі обмеження

- **Мова журналу змін.** Історія статусів розбирається за текстом запису («Status changed from … to …» або українською). Мова береться з налаштувань користувача, чий токен використовується. Якщо в `data/latest.json` поле `statusHistoryUnparsed` велике, додайте свій шаблон у `STATUS_CHANGE_PATTERNS`.
- **Права.** Записи часу бачать лише ті, хто має відповідне право в проєкті. Якщо `timeEntries` порожній, перевірте права користувача токена.
- **Час запуску.** GitHub Actions працює за UTC, тому після переходу на зимовий час запуск зсувається на годину раніше.
